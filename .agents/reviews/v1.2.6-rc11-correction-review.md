# Pinova v1.2.6-rc11 correction review

Reviewed on 2026-09-20 against the exact `main` baseline before implementation. This record intentionally omits production host paths, account identifiers, raw URLs with private query data, cookies, nonces, OTP values, and operational logs.

## Decision

The production report is approved as the basis for a focused 1.2.6 correction, with two causality limits preserved:

- completion of `wp_logout()` followed by a blank response is proven, and the unconditional `exit` after `wp_safe_redirect()` is a concrete resilience defect; the exact external condition that rejected or prevented the live redirect was not proven;
- purpose-specific OTP records and endpoint enforcement are working, while the observed second email and the exact code entered were not captured; ambiguous all-purpose email copy is a concrete user-confusion defect, but an unintended client request was not proven.

Subsequent disposable-browser regression testing reproduced a plugin-side empty-location path: WordPress keeps an empty value passed to `wp_validate_redirect()` instead of replacing it with the supplied fallback. The live request's complete external conditions remain unavailable, but the correction now removes this reproducible cause as well as retaining the controlled redirect-failure fallback.

The absence of an administrator OTP copy is expected security behavior and is not a defect. Native-login gate policy, identity migration, server tuning, theme changes, database operations, and production deployment are outside this correction.

## Approved correction

- Generate Pinova logout URLs directly on canonical `/logout/`.
- Resolve omitted or empty login/logout return targets explicitly to their safe role-aware/site fallback before redirect validation.
- Validate the logout nonce before session destruction and return controlled HTTP 403 for invalid or stale links.
- Check the result of the validated safe redirect. If WordPress rejects it, render a nonblank controlled fallback with a same-site continuation link and emit privacy-safe `auth.redirect_failed` context only.
- Preserve separate active OTP records for login/registration and password recovery.
- Give login, registration, and password-recovery emails distinct subjects and body instructions without copying OTPs to administrators.

## Required evidence

- Integration coverage for invalid nonce, redirect rejection, session state, privacy-safe logging, concurrent OTP purposes, and purpose-specific email delivery.
- Real browser HTTP coverage for authenticated `/logout/` returning 3xx plus `Location` and a reused link returning 403.
- Full PHP, WordPress/WooCommerce, browser, static-analysis, coding-standard, package, and compatibility checks on GitHub Actions.
- Reviewed merge to `main`, successful merged-main Quality, immutable `v1.2.6-rc11`, attestations, checksum/integrity checks, and an independent redownload before the asset is offered for installation.

Publication does not authorize installation or any production-site mutation.
