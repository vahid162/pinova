# Pinova v1.2.6-rc12 redirect correction review

Reviewed on 2026-09-21 after immutable RC11 publication and independent handoff verification.

## Decision

RC11 must be preserved but superseded before installation. Its redirect helper exits when `wp_safe_redirect()` returns `true`, although WordPress can return that value after PHP output has already committed the response headers. The [WordPress core `wp_redirect()` implementation](https://developer.wordpress.org/reference/functions/wp_redirect/#source) calls PHP's header functions and then returns `true` without a `headers_sent()` guard. In that state no usable `Location` header is guaranteed and RC11 bypasses its controlled fallback.

The correction retains the same logout-resilience scope and also includes one bounded modal-focus defect exposed by the mandatory merged-main browser gate. It does not change OTP behavior, identity resolution, native-login policy, registration policy, the database schema, plugin settings, or site/server configuration.

## Approved correction

- Inspect header state before dispatching a safe redirect.
- Inspect it again before accepting a truthy redirect result and exiting.
- If headers are already committed, render the same nonblank controlled continuation fallback and emit only bounded `auth.redirect_failed` context with `headers_sent` reason/status codes.
- Retain the existing rejected-redirect fallback, safe same-site URL validation, logout nonce semantics, session destruction order, and privacy constraints.
- Add an integration regression that simulates a redirect reporting success as header state becomes unavailable; verify fallback content/status metadata and absence of destination secrets in the structured event.
- When WooCommerce replaces the checkout fragment containing the captured modal opener, restore focus to the equivalent connected opener after close while retaining lifecycle-token protection against stale callbacks.
- Make the real-browser pending-request case replace its opener deterministically before closing; do not add retries, arbitrary waiting, or a weaker assertion.

## Required delivery evidence

- Full PHP 8.1–8.5, static analysis, coding standards, WordPress/WooCommerce/HPOS integration, JavaScript, browser, package, and compatibility checks on GitHub Actions.
- Focused PR from corrected `main`, exact-head green CI, merge, and a separate merged-main green run.
- Next unused immutable candidate `v1.2.6-rc12`, with two byte-identical builds, annotated tag, Release/asset attestations, SHA-256, ZIP integrity, one `pinova/` root, independent redownload, and RC11-to-RC12 package comparison.

No production installation or site mutation is authorized by this review.
