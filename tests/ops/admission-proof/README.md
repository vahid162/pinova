# Never-merge native admission proof

This isolated seven-case protocol tests the extracted persistent filesystem gate and four neutralized reader adapters. It is not an application fix, resource acceptance, production drain proof, or deployment approval. The branch must never merge.

The single hosted Ubuntu job downloads and extracts the distribution Nginx package into its own temporary directory. It does not install the package or operate a system service. A root-owned foreground master has an unprivileged worker; only three high loopback ports and a tiny Python fixture backend are used. No PHP, WordPress, database, provider, SSH or credentials participate.

The fixed cases cover exact-open admission, closed admission on an existing keep-alive connection despite inherited file caching, denied directory traversal and invalid cron tokens, a cron wrapper started while its parent holds the lock, the death of its owned lease-holder, verified reopening plus refusal of foreign identities, and availability of an unrelated server throughout. Actual root ownership, Linux no-replace rename, fsync, flock and termination of the fixture child execute here. The wrapper readiness signal precedes flock: case4 proves source placement after the lock and defer after release, but does not attest a kernel-blocked waiter. Readiness polling does not rerun acceptance requests. A failed case stops the remaining cases, preserves failure, and attempts a verified hold before bounded cleanup of owned processes.

All five Nginx temporary directories are explicitly under the owned run prefix and writable by its unprivileged worker. Native pidfd APIs are required; there is no process-group or global signal fallback. Every process launch is registered before identity capture. Cleanup inventories only this controller's direct/adopted child tree and binds identities to recorded launch sessions and start ticks. Unknown identities receive no signals and fail cleanup; other owned resources still receive cleanup. Acceptance requires an empty final own-child inventory as well as reaping the known launches and descendants.

The helper bodies are extracted without algorithm changes. Only the admission directory constant is substituted. The three guard fragments preserve their comparisons and defer exits; only neutral admission and log destinations are substituted. The fixture acquires its real final flock before each fragment. Private source review establishes placement in the real wrappers; these fixtures do not execute or publish the production wrapper bodies.

Nginx tests file existence, not token contents, ownership or symlink provenance. Root ownership and exclusive writes to its parent directory remain prerequisites. Denying traversal is tested; chmod000 on a stat-able token is not treated as an HTTP denial. Native filesystem failure injection, reboot/disk durability, production ACLs, loaded configuration, production ingress completeness, application draining, package verification and supervisor recovery are outside this proof. The separate bounded supervisor controls cover recovery decisions; native refusal tests here do not replace them.

These are fresh fixture readers. Production must separately demonstrate that every Nginx worker generation which loaded the pre-guard configuration has retired naturally after its graceful reload, including old keep-alive and in-flight readers. Every pre-guard cron wrapper instance, including lock waiters and staggered sleepers with an old loaded script body, must also have exited before hold. This preparation happens while admission remains open, outside the supervisor's critical deadline; syntax validation, source hashes and a generic writer assertion do not establish retirement. No global worker killing or restart is authorized by this proof.

Only a finite JSON receipt is uploaded. Raw setup/runtime stderr, generated configuration and request bodies remain private to the disposable runner. Every case and owned-process cleanup must pass; setup failures and unexecuted cases cannot count as acceptance. The native cases have a 180-second deadline plus 15 seconds for cleanup, within a single ten-minute job. Attempt 1 only; no retries or automatic reruns.
